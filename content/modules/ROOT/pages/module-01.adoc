== OpenShift Virtualization Introduction and Feature Review

OpenShift Virtualizationは、Red Hat OpenShiftの機能として、スケーラブルでエンタープライズグレードの仮想化機能を提供します。これを使用して、仮想マシン（VM）を専用に管理したり、コンテナワークロードと並行して管理したりできます。

image::rh1/02-ocp-virt-arch.png[link="self", window=blank, width="100%"]

OpenShift Virtualizationは、Kubernetesのカスタムリソースを使用して仮想化タスクを可能にすることで、OpenShift Container Platformクラスターに新しいオブジェクトを追加します。これらのタスクには以下が含まれます。

* LinuxおよびWindows VMの作成と管理
* クラスター内でのポッドとVMワークロードの並行実行
* さまざまコンソールやCLIツールを介したVMへの接続
* 既存のVMのインポートおよびクローン作成
* VMにアタッチされたネットワークインターフェースコントローラー（NIC）およびストレージディスクの管理
* ノード間でのVMのライブマイグレーション

== Objectives（目的）

* 受講者は、OpenShift Virtualizationの機能についての簡単なレビューに参加します。
* 受講者は、OpenShift Virtualizationで利用可能なプロビジョニングオプションを確認し、シンプルなVMを作成します。
* 受講者は、OpenShift Lightspeedに指示を出して支援を受けながら、カスタムVMを作成します。
* 受講者は、OpenShift LightSpeedを使用して、VMデプロイメントの失敗をトラブルシューティングします。

== Introduction to OpenShift Lightspeed

ご存じない方のために説明すると、 https://www.redhat.com/en/technologies/cloud-computing/openshift/lightspeed[OpenShift Lightspeed^]  は、Red Hat OpenShiftのWebコンソールに直接統合された、生成AIを搭載したアシスタントです。質問への回答、コマンドの提案、自然言語によるYAML構成の分析を通じて、ユーザーによるトラブルシューティング、理解、およびOpenShiftクラスターの管理を支援し、適切なサポートのために様々な大規模言語モデル（LLM）と連携します。 +

このモジュールの残りの部分では、OpenShift Lightspeedを活用して、情報収集からリソースの作成やトラブルシューティングにいたるまで、クラスター内でのいくつかのタスクを実行します。

[[create-vm-lightspeed]]
== Create a VM from an OpenShift Lightspeed Prompt

VMをクイック作成することは一つのアプローチです。これはお客様にOpenShift Virtualizationが基本的に「動作する」ことを示し、使いやすさや、現在のハイパーバイザーとユーザー体験がどう異なるかといった最も基本的な疑問への回答になります。

実際のVMのユースケースでは、仮想マシン自体のカスタマイズや構成だけでなく、それがホストするワークロード、つまり本質的なVMの用途が絡んできます。ここで、OpenShift Lightspeedのようなツールが、プラットフォームに不慣れな人でも迅速にアクションを実行できるように支援します。

OpenShiftクラスターやそこで実行されているワークロードに関する質問に答えるだけでなく、OpenShift Lightspeedはリソースの作成を支援するためにも使用できます。現在は自動でクラスター管理操作を実行する機能は持っていませんが、それらのアクションを実行するために使用できる構成例（マニフェスト）を提供してくれます。

このタスクでは、特定の目的のための仮想マシンの作成を支援してもらうよう、OpenShift Lightspeedにプロンプトを投入します。応答があったら、提供された内容を使用して必要な仮想マシンを作成します。

=== Create a Prompt for the VM.

私たちのタスクは、エンドユーザーによる追加の構成なしで、デフォルトでデータベースサーバーとして機能する仮想マシンを作成することです。

以下のプロンプトをコピーしてOpenShift Lightspeedに貼り付け、準備ができたら `Send（送信）` ボタンをクリックしてください。

[source,shell,subs=attributes,role=execute]
----
Create a YAML manifest that creates a VM in the {user}-vms project that has CentOS Stream 9 as it's operating system, to be used as a database-server. Configure it with a username and password through cloudinit, and automatically install mariadb and configure it to run on startup.
----
image::rh1/28-create-vm-prompt.png[link="self", window=blank, width="100%"]

OpenShift Lightspeedは、要求されたVMを作成するために使用できるYAMLマニフェストと、その回答を提供した根拠を返答します。

image::rh1/29-create-vm-answer.png[link="self", window=blank, width="100%"]

[NOTE]
====
生成AIの性質上、返ってくる回答が上記のスクリーンショットと完全に一致しない可能性があります。
====
提供されるYAMLは以下のようになります。

[source,yaml,subs=attributes,role=execute]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: database-server
  namespace: {user}-vms
spec:
  running: true
  template:
    metadata:
      labels:
        kubevirt.io/vm: database-server
    spec:
      domain:
        cpu:
          cores: 2
        devices:
          disks:
          - name: rootdisk
            disk:
              bus: virtio
          - name: cloudinitdisk
            disk:
              bus: virtio
        resources:
          requests:
            memory: 4Gi
      volumes:
      - name: rootdisk
        containerDisk:
          image: quay.io/containerdisks/centos-stream:9
      - name: cloudinitdisk
        cloudInitNoCloud:
          userData: |-
            #cloud-config
            user: dbadmin
            password: dbpassword
            chpasswd: { expire: False}
            packages:
              - mariadb-server
            runcmd:
              - systemctl enable mariadb
              - systemctl start mariadb
----

上記のYAMLをコピーした後、OpenShiftのプラス（＋）ボタン（クイック作成）を使用してVMをデプロイできます。

コンソールの最上部にあるプラス（＋）ボタン（インポートボタン）をクリックし、ドロップダウンメニューから `Import YAML（YAML のインポート）` を選択します。

image::rh1/30-quick-create-yaml.png[link="self", window=blank, width="100%"]

提供されたYAMLマニフェストを貼り付け、下部にある `Create（作成）` ボタンをクリックします。

image::rh1/31-paste-yaml.png[link="self", window=blank, width="100%"]

VMのプロビジョニングが開始され、数秒後に `Running（実行中）` 状態になります。指示通り `{user}-vms` ネームスペースに配置され、名前は `database-server` で、CentOS Stream 9 オペレーティングシステムが実行されていることが確認できます。

image::rh1/32-lightspeed-vm-running.png[link="self", window=blank, width="100%"]

`Console（コンソール）` タブをクリックし、資格情報を使用してログインして、以下のコマンドを使用して mariadb がインストールされ実行されていることを検証します。

[source,shell,subs=attributes,role=execute]
----
sudo mysql -u root
----

image::rh1/33-lightspeed-vm-console.png[link="self", window=blank, width="100%"]

[[troubleshoot-vm-lightspeed]]
== Troubleshoot a VM with OpenShift Lightspeed

プラットフォームに関する基本的な質問への回答や、VMのデプロイやその他のリソース作成に使用できる構成の生成に加えて、OpenShift Lightspeedは、プラットフォームやアプリケーションの問題のトラブルシューティングにも使用できます。

このタスクでは、意図的に失敗するようにVMを構成し、OpenShift Lightspeedに問題を診断できるかどうかを尋ねて、どのような回答が得られるかを確認します。

`{user}-vms` プロジェクトにいることを確認し、右上の `Create（作成）` ボタンをクリックして、ドロップダウンメニューから `From template（テンプレートから）` オプションを選択します。

image::rh1/34-create-vm-from-template.png[link="self", window=blank, width="100%"]

`Create new VirtualMachine（新しい VirtualMachine の作成）` ページで、Fedora VMのタイルを選択します。

image::rh1/35-fedora-tile.png[link="self", window=blank, width="100%"]

Fedora VMのダイアログが表示されたら、仮想マシンの名前に fedora-broken と入力し、Customize VirtualMachine（仮VirtualMachineのカスタマイズ） ボタンをクリックします

image::rh1/36-customize-vm.png[link="self", window=blank, width="100%"]

`Customize and create VirtualMachine（VirtualMachine のカスタマイズと作成）` ページで、`Disks（ディスク）` のタブをクリックし、デフォルトの rootdisk の横にある `3つのドット` のメニューをクリックして `Edit（編集）` オプションを選択します。

image::rh1/37-edit-disk.png[link="self", window=blank, width="100%"]

`Edit disk（ディスクの編集）` ダイアログが表示されたら、ディスクサイズを *10GB* に変更します。これは、VMを正しくプロビジョニングするには小さすぎるサイズです。ダイアログの `Save（保存）` ボタンをクリックし、メイン画面に戻ったら `Create VirtualMachine（VirtualMachineの作成）` ボタンをクリックします。

image::rh1/38-edit-disk-small.png[link="self", window=blank, width="100%"]

[NOTE]
====
この時点で、OpenShift Virtualizationにおけるブートイメージの仕組みに不慣れな管理者は、ストレージ容量を節約するために小さなハードディスクでVMを作成したと考えている可能性が高いと推測されます。そして、なぜVMが正常に起動しないのか困惑するかもしれません。
====

VMは `Provisioning（プロビジョニング中）` 状態のままになり、それ以上進むのに失敗します。

image::rh1/39-vm-provisioning.png[link="self", window=blank, width="100%"]

`Events（イベント）` タブをクリックすると、DataVolumeが作成されたことは表示されますが、それ以上の追加情報はありません。

image::rh1/40-vm-events.png[link="self", window=blank, width="100%"]

プラットフォームに不慣れな仮想化管理者の立場になって、ここでOpenShift Lightspeedに助けを求めます。

右下隅にあるOpenShift Lightspeedのアイコンをクリックし、なぜVMが起動できないのかを質問して、`Send（送信）` ボタンをクリックします。

[source,shell,subs=attributes,role=execute]
----
Why is the VM fedora-broken in the {user}-vms project failing to boot?
----

image::rh1/41-broken-lightspeed-prompt.png[link="self", window=blank, width="100%"]

OpenShift Lightspeedは、問題をストレージ関連として診断し、DataVolumeが必要なサイズよりも小さいというエラーメッセージを提示し、潜在的な解決策を提供することができます。

image::rh1/42-broken-lightspeed-answer.png[link="self", window=blank, width="100%"]

[NOTE]
====
生成AIの性質上、返ってくる回答が上記のスクリーンショットと完全に一致しない可能性があります。
====

[IMPORTANT]
====
次のセクションに進む前に、リソースを節約しスムーズなラボ体験を確保するために、このモジュールの一環として *{user}-vms* プロジェクトで作成したVMがすべてシャットダウン、および/または削除されていることを確認してください。これらは以降使用しません。
